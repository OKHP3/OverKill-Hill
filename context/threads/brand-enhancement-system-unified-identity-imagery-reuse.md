## Decisions and rationale

### 1. Treat the ecosystem as one family with three roles

The most useful organizing model is shared grammar plus differentiated role. A visitor should recognize a common system through spacing, structure, icon discipline, and cross-links, while the emotional promise changes by brand. This protects recognition without making Glee-fully, Ask Jamie, and OverKill Hill P³ interchangeable.

### 2. Make OverKill Hill P³ the systems authority

The current repository is the OverKill Hill P³ source of truth for the canonical shared CSS and JavaScript foundation. Future cross-brand changes should begin here, preserve the static-site constraint, and then propagate through the documented sibling workflow. The historical ChatGPT response is not authorization to rebuild the site or introduce a separate app framework.

### 3. Reconcile, do not blindly adopt, the `data-brand` proposal

The proposed token model is structurally sound: brand definitions should map to live UI tokens, while components consume semantic variables. However, the current repository already uses `data-theme` on `html` for light and dark behavior and body scope classes for sibling-brand divergence. The next design decision is whether to add a normalized `data-brand` attribute as a compatibility layer or to keep the existing body hooks and formalize their token map. Either choice requires a small proof on all three sibling sites, accessibility review, and visual regression checks.

### 4. Keep the current OverKill Hill font and color contract authoritative

The source's alternate font trio and proposed palette values are historical suggestions. The repository contract names Alfa Slab One, DM Sans, and JetBrains Mono, with rust-orange and amber accents over teal, warm paper, and espresso or slate surfaces. A family bridge should be built from semantic spacing, line, motion, and relationship tokens first. Do not introduce Glee-fully coral or Ask Jamie aqua as primary OverKill Hill accents.

### 5. Treat the manifesto as a brand operating system, not only a page

The manifesto's strongest reusable rules are operational. The first answer is material, not final. Human judgment remains responsible for comparison and adjudication. Diagrams must reduce cognitive load and preserve truth. Governance protects meaning from drift. Joy supports adoption. These principles should inform voice, page structure, asset review, and release checks.

### 6. Separate locked canon from living exploration

Origin, generational record, and MurderBird provenance belong in a locked reference layer. New campaign imagery, alternate crops, motion tests, and cross-brand applications belong in a living layer with version labels and review status. This prevents an experiment from silently rewriting the visual identity while allowing the brand to evolve.

### 7. Do not delete the source thread until generated assets are durable

The Notion archive identifies the generated Glee-fully and MurderBird images as the largest loss risk. Before any source thread is archived or deleted, save the binaries, canonical prompts, creation date if known, variant relationship, and intended use. If the binaries cannot be recovered, retain the descriptions and mark the visual reconstruction as a new generation rather than a restoration.

## Reusable methods and assets

### Brand family grammar

Use a five-part shared layer:

1. **Geometry:** shared spacing ratios, container widths, radius logic, and stroke rules.
2. **Type system:** shared hierarchy and reading rhythm, with each brand using only approved fonts.
3. **Motion DNA:** one short reveal pattern that can be recolored and slowed or simplified per brand.
4. **Bridge layer:** reciprocal footer links, favicon echoes, and a small set of shared symbols.
5. **Token discipline:** components consume semantic tokens such as surface, ink, muted, accent, border, and focus. Brand scopes define values.
