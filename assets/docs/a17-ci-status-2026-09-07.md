# A17: CI concurrency and status reporting

Baseline: `98922aebf71d90b2b18ecc34c8b00a041fff51c7`. Isolated branch:
`codex/a17-ci-status`. Findings D07/D08 reproduce in current source.

## Reproduction and scope

The baseline reusable validation and standalone validation have the same
workflow-level event/ref group with cancellation enabled. The archived
September 7 delivery record shows standalone run 34084297864 canceled while
Pages run 34084298158 passed. That observation does not establish the cause
of cancellation or show unvalidated deployment. Pages still requires validation.

The baseline Actions monitor prints PARTIAL as external unavailability even
when the report records accepted Pages policy limitations. The retained
`assessment-2026-09-07/delivery/live-edge.json` contains 428 checks, 315 warnings,
39 blocked checks and zero failures. This is historical fixture evidence,
not a fresh live-site acceptance result.

## Changes

- Validation concurrency moves to its job. Caller workflow name separates
  standalone and reusable runs. PR revisions share a PR-ref group; push and
  manual runs use their run ID, isolating retries from other release runs.
- Monitor groups separate caller, trigger and manual-run identity. Scheduled
  repeats can supersede old scheduled monitor work only.
- The Pages deployment group remains `pages`, with cancellation disabled.
  GitHub concurrency is not a FIFO queue: pending deployments can be replaced.
  This patch preserves the existing deployment policy and does not guarantee
  every rapid push deploys or impose newest-SHA ordering.
- Actions summaries distinguish sampled content delivery, edge policy and
  external availability. Release-manifest evidence and expected SHA are shown
  separately from workflow checkout SHA, including in scheduled monitoring.
- Repeated warnings and blocked checks are grouped by status/evidence. Full
  route reports remain uploaded. PARTIAL remains PARTIAL; no policy is weakened.
- Missing, malformed or empty reports fail closed with UNKNOWN evidence.
  Confirmed first-party or policy failures fail classification. External
  outages and CSP diagnostics retain their non-blocking health-signal behavior;
  confirmed local browser route failures now fail their monitoring job.

The reporter reads existing reports only. It neither performs network requests
nor writes source/generated content. Its grouping uses the current verifier's
check labels; unfamiliar checks stay in content so new failures remain visible.
