# W05 — FoundRy redirect and launch regression

## Scope

Added `tests/test-foundry-launch-routes.py`, a standard-library regression
check for the legacy `/found-ry/` route, canonical `/projects/found-ry/`, the
direct GitHub Pages workbench URL, and accidental GPT-studio route references.
The test reads `site-src/pages/projects/found-ry/index.main.html` as the
authoring source and `projects/found-ry/index.html` plus `found-ry/index.html`
as generated/public boundaries. It does not fetch the external app.

## Evidence

- The canonical page consistently launches
  `https://okhp3.github.io/OverKill-Hill-FoundRy/` from the authoring and
  generated surfaces.
- The canonical page links to `/projects/found-ry/` and contains the expected
  embedded workbench frame.
- No confusing `/studio/`, ChatGPT GPT-builder, or legacy FoundRy studio URL is
  present in those surfaces.
- The legacy page contains a canonical destination and manual continuation
  link, but no automatic redirect marker. The focused regression therefore
  reproduces this current defect rather than weakening the expected behavior.

## Validation

Command:

```text
python3 tests/test-foundry-launch-routes.py
```

Result: 1 failing test, `test_legacy_route_redirects_to_canonical_route`,
because `found-ry/index.html` has no automatic redirect. The other four route
and launch checks pass.

The broader site validator, browser checks, generated-site checks, and live
HTTP redirect behavior were not run in this focused task. No source, config,
HTML, workflow, or dependency files were changed.
