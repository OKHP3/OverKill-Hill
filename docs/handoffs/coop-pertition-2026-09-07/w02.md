# W02 — FoundRy embed acceptance harness

Status: complete, local candidate commit only.

## Scope and invocation

This task owns `tests/foundry-embed-acceptance.test.mjs` and this handoff. It
checks the generated FoundRy project page at `/projects/found-ry/` using the
existing root Playwright dependency and a temporary loopback HTTP server. Run
it from the repository root with:

```bash
node --test tests/foundry-embed-acceptance.test.mjs
```

`PORT=21102 node --test tests/foundry-embed-acceptance.test.mjs` is also
supported when a deterministic local port is useful. The harness does not add
dependencies, edit source/runtime files, or broaden the iframe sandbox.

## Acceptance evidence

The harness records current parent-page behavior:

- the iframe points to `https://okhp3.github.io/OverKill-Hill-FoundRy/`;
- the iframe keeps `allow-scripts allow-same-origin allow-forms`, with no
  `allow-downloads`, and denies clipboard and fullscreen permissions;
- the iframe has the current title and strict cross-origin referrer policy;
- the reload button is enabled, labeled, titled, keyboard focusable, and
  reloads the child frame while keeping the parent URL in place;
- at least three current target-blank direct-app links are present (hero,
  toolbar, and slow-load fallback), so a visitor has a usable full-screen
  escape path.

## Limits

This is a bounded parent-page harness. It does not claim full browser coverage
of the external GitHub Pages app, its internal localStorage recovery, backup
schema, export bytes, or browser download behavior. The iframe sandbox
deliberately omits `allow-downloads`; therefore downloads initiated inside the
embedded child are not asserted as working. Direct-app backup/export behavior
requires a separate run against the deployed child app and remains outside
this repository's acceptance evidence.

Validation result: both tests pass locally with the existing Playwright
installation.
